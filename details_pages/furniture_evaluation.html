Table assistant_models_nav_convNavigation and conversation columns used in experiments_results_with_figures_tables.tex.

Table assistant_models_nav_conv

Navigation and conversation columns used in experiments_results_with_figures_tables.tex.

Data location

  • LaTeX: runs/runs_supermarket/experiments_results_with_figures_tables.tex, table tab:assistant_models_nav_conv
  • Definitions: runs/runs_supermarket/appendix_revised_sections_to_replace.tex, app:metric-definitions
  • Methodology source: new_evaluation_metrics_all_users.md
  • Exports: new_evaluation_metrics.json/csv/md
  • Source script: sitrec/metrics/compute_supermarket_metrics.py

Metric fields

  • AFR -> AFR micro
  • LNSR_g -> LNSR global
  • TAR -> MoveToLocationAchievable
  • Judge, Ground., Pref., Prog.

Calculation

  • AFR micro = count(local_tool_match == true) / count(valid expected_user_tool events).
  • LNSR global = count(correct tool type and correct comparable local parameter) / count(valid comparable expected actions).
  • TAR uses MoveToLocationAchievable: count(move-to-location targets present in the current SOM/OBS mapping) / count(checkable move-to-location targets). Supermarket events use move_to_fixture and fixture_id; furniture events use store/area targets.
  • VisibleTargetAFR, InvisibleTargetMoveToRate, and by-action AFR/LNSR are diagnostic exports, but the main nav table uses AFR micro, LNSR global, and TAR.
  • Judge columns use scored episode-level llm_judge_events; Ground., Pref., and Prog. map to groundedness, preference_alignment, and intent_progress.
  • Navigation rates are shown as percentage points; judge scores remain on the 1-5 scale.
Table recommendation_assistant_modelsOutcome and recommendation-quality columns used by the main recommendation table.

Table recommendation_assistant_models

Outcome and recommendation-quality columns used by the main recommendation table.

Data location

  • LaTeX: table tab:recommendation_assistant_models
  • Inputs: raw terminal_summary.json plus processed assistant_recommendations.jsonl and evaluation_result.json
  • Methodology source: new_evaluation_metrics_all_users.md
  • Exports: new_evaluation_metrics.json/csv/md

Metric fields

  • SR -> CartAdd
  • Rec_succ -> AvgRecCountCartAdd
  • T -> AvgTurns
  • T_succ -> AvgCartAddDialogueRound
  • R@5/R@10 -> Cart-R@5/Cart-R@10
  • MRR@10/NDCG@10 -> Cart-MRR@10/Cart-NDCG@10

Calculation

  • CartAdd = count(included episodes with a final cart item) / included episodes.
  • AvgTurns = average(terminal_summary.json.steps + 1); stored steps are 0-based and exported table turns are 1-based.
  • AvgCartAddDialogueRound = average 1-based dialogue round where cart add succeeds.
  • AvgRecCountCartAdd = average explicit Recommend count in cart-add episodes; AvgRecCountNoCartAdd does the same for no-cart episodes.
  • Cart-R@K = ranking turns where the final cart item appears in Top-K / ranking turns in successful episodes.
  • Cart-MRR@10 = average(1 / rank_of_final_cart_item) when rank <= 10, otherwise 0.
  • Cart-NDCG@10 = average final-cart-item DCG@10; with one relevant cart item, IDCG@10 = 1.
Table goal_visibility_analysisNavigation-goal density and cumulative visibility metrics used by the CGV table and trajectories.

Table goal_visibility_analysis

Navigation-goal density and cumulative visibility metrics used by the CGV table and trajectories.

Data location

  • LaTeX: table tab:goal_visibility_analysis and figure fig:cgv_trajectories
  • Inputs: events/navigation_events.jsonl plus dialogue OBS snapshots
  • Methodology source: new_evaluation_metrics_all_users.md and compute_supermarket_metrics.py
  • Exports: new_evaluation_metrics.json/csv/md navigation section

Metric fields

  • N_goal
  • AvgCnt
  • Var.
  • Rep.
  • CGV_0, CGV_+1, CGV_+2, CGV_+3, CGV_+4, CGV_+5, CGV_any

Calculation

  • N_goal = navigation_goal_event_count from events with a navigation_goal.
  • AvgCnt = NavigationGoalCountAvg = navigation goal events / included episodes.
  • Var. = NavigationGoalVarietyAvg = average distinct navigation-goal fixtures per included episode.
  • Rep. = NavigationGoalRepeatRateAvg = average within-episode repeat rate, 1 - distinct goals / goal events.
  • CGV_0 = GoalVisibleCumulativeNow.
  • CGV_+1/+2/+3/+4/+5 = GoalVisibleCumulativeNext/Within2/Within3/Within4/Within5Rounds.
  • CGV_any = GoalVisibleCumulativeAnyFutureRound.
  • All cumulative CGV fields use GoalVisibleCumulativeDenominator, so the trajectory points are comparable.
  • Visibility is checked against objective OBS.visible_fixtures, not the assistant's self-reported goal_visible field.

Metric fields

  • MaxTurn Rate
  • Rec_MT
  • RecFail@3 Rate
  • T_3rec
  • Leak
  • LeakEp

Calculation

  • MaxTurn rate = completed episodes ending at max_turn_reached without cart add / completed episodes.
  • Rec_MT = AvgRecCountMaxTurnFailure = average explicit recommendations in max-turn no-cart episodes.
  • RecFail@3 rate = completed episodes ending after three failed recommendations / completed episodes.
  • T_3rec = AvgRecFail@3Turn = average terminal turn for recommendation-exhausted episodes.
  • Leak = InfoLeakageRate = user-facing assistant_response rows matching internal-symbol leakage rules / non-empty assistant_response rows.
  • LeakEp = InfoLeakageEpisodeRate = included episodes with at least one leaked user-facing assistant_response / included episodes.
  • The leakage detector scans delivered assistant text only; it does not scan internal assistant_actions or recommendation_ranking fields.

navigationDid the customer locally follow the assistant's navigation/action guidance?

navigation

Did the customer locally follow the assistant's navigation/action guidance?

Data location

  • Inputs: processed events/navigation_events.jsonl
  • Per-run output: processed evaluation/evaluation_result.json.navigation
  • Batch output: processed aggregate_evaluation.json.navigation

Metric fields

  • event_count
  • local_tool_match_rate
  • local_fixture_id_match_rate / local_store_id_match_rate / local_area_id_match_rate / local_item_id_match_rate
  • local_navigation_target_match_rate
  • waypoint_visible_rate
  • goal_visible_rate

Calculation

  • local_tool_match_rate = count(local_tool_match == true) / navigation event_count.
  • Target match rates use only events with the corresponding expected_* id.
  • local_navigation_target_match_rate = matched target events / events with expected_navigation_target.
  • waypoint_visible_rate and goal_visible_rate count visible flags over all navigation events.
  • In aggregate, micro_* recomputes over all events; macro_* averages per-run rates.
recommendation rankingDid the assistant's ranked list contain the exact target or an acceptable item?

recommendation ranking

Did the assistant's ranked list contain the exact target or an acceptable item?

Data location

  • Inputs: raw runtime_turn_records recommendation_ranking plus processed benchmark_spec relevance_sets
  • Intermediate: processed evaluation/evaluator_result.json.by_turn
  • Per-run output: processed evaluation/evaluation_result.json.recommendation
  • Batch output: processed aggregate_evaluation.json.recommendation

Metric fields

  • exact_recall_at_1/5/10
  • exact_mrr_at_1/5/10
  • exact_ndcg_at_1/5/10
  • acceptable_recall_at_1/5/10
  • acceptable_mrr_at_1/5/10
  • acceptable_ndcg_at_1/5/10
  • first_exact_hit_turn and first_acceptable_hit_turn

Calculation

  • Recall@k is 1 for a turn if a relevant item appears at rank <= k, then averaged over ranking turns.
  • MRR@k uses 1 / first_relevant_rank when that rank is <= k, otherwise 0.
  • NDCG@k discounts relevant ranks by log2(rank + 1) and normalizes by ideal DCG for the relevant set size.
  • Exact metrics use one relevant item; acceptable metrics use relevance_sets.acceptable_items.

Planned 20 x 100 Run Plan

The formal English run is staged but cumulative: first one episode for the gpt-5.6-sol pair, then the first goal of all 25 profiles for that pair, then the same 25 profile-first goals for all 10 pairs, then all 100 goals for the five gpt-5.6-sol User pairs (Stage 4), the first two goals of every profile for the five gpt-4o User pairs (Stage 5, 50 goals per pair), and finally all 100 goals for those gpt-4o User pairs (Stage 6). Every stage writes to the same experiment/model-cell folders and Resume skips complete episodes. In ordered_predefined mode, episode 1 maps to the first predefined shopping goal, episode 2 to the second, and so on in file order.

Raw / processed contract

Immutable evidence is separated from every reproducible annotation, score, and aggregate.

Data location

  • Automatic raw: outputs/raw/<scene>/<cell>/<episode>/
  • Automatic processed: outputs/processed/<scene>/<cell>/<episode>/
  • Human raw: web/sitrec_chat/evaluation_data/人文评估/raw/<model>/<profile>/<run>/
  • Human processed: web/sitrec_chat/evaluation_data/人文评估/processed/<model>/<profile>/<run>/

Metric fields

  • raw cell source_snapshot/manifest.json, source_snapshots/<snapshot_id>/manifest.json, source_snapshot_compatibility.json, and per-episode metadata/source_snapshot_ref.json
  • processed/processing_manifest.json
  • offline rebuild scripts that make no UE or model requests

Calculation

  • Raw keeps exact dialogue, model/provider responses, executed actions, observations, survey submissions, terminal state, and frozen source inputs.
  • Processed keeps benchmark labels, match flags, schema validation, normalized judge scores, human-evaluation summaries, and metric aggregates.
  • Every processed manifest hashes its raw dependencies, source snapshot, formula files, and outputs.
  • A reviewed compatibility transition preserves the original snapshot, approves one exact baseline-to-current snapshot-id pair without chaining, and binds every episode to the immutable snapshot it actually used; completed episodes keep their old references and only new episodes use the successor.
  • The approval names schema, scene, evaluation kind, both snapshot ids, and a nonempty reason; changed entries must be Python sources categorized as formula, visual_runtime, or runtime_input.
  • Resume preflights the exact source plan before scanning old episodes, writing batch or launch configuration, creating an episode, or connecting to UE, then freezes the same plan when the episode starts.
  • The cell's initial experiment_config.json is retained; every launch writes launches/<launch_id>/experiment_config.json with its selected source_snapshot_ref.
  • Approval is tied to exact hashes and requires code review of behavior; extra drift and catalog, prompt, profile/goal, map data, or other non-code benchmark-input changes stop the run.
